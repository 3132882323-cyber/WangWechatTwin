# 本机语音试听

文字回复、语音合成和微信原生语音发送是三条不同的链路。当前微信发送接口支持文字及图片；本说明的命令只保存本机音频，不能把音频文件附件当作微信语音条。

## 豆包预设音色

`app.doubao_voice` 使用本人已授权的豆包 QR 会话产生单句预览。语音接口需要原会话中的 `sessionid_ss`；不能伪造登录字段或从其他浏览器批量采集凭据。网页服务的协议和可用性仍可能变化。

```text
python -m app.doubao_voice --help
```

命令需要一份私有会话文件、仅含已授权朗读文字的 UTF-8 文件、私有输出目录和唯一请求编号。必须有 ffmpeg 与 ffprobe；接收到的 AAC 先验证再转换成 MP3，再次验证后才发布。输入目前限一整句，服务返回的朗读文字须与完整输入一致。未完成、未知或已经完成的请求编号都不能重提。

这是豆包**预设音色**，不代表用户本人声线。真人声线需要单独的参考声音、来源核对和本机或另经授权的声线模型。不要把已有联系人发送的语音当作本人的参考，也不要把参考录音、会话文件、模型缓存或生成音频提交到仓库。

## 本人声线

提供独立的 `scripts/generate_voice_clone.py`，使用官方 [llama.cpp TTS](https://github.com/ggml-org/llama.cpp/blob/master/tools/tts/README.md) 与 [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) Base GGUF 在本机生成本人参考声线。其本机推理与豆包网页预设音色不同，不上传参考声音。

当前校验固定 Windows CUDA 12.4 的 b10679 二进制与官方 1.7B Base Q4_K_M/Q8 音频投影模型。CLI 不下载或安装模型，不升级微信后台的 Python；需要先从官方来源准备、核验资产。参考音频只应来自已核对、本人确认的录音，转写不确定时不能把它当作可信字稿。

```text
python scripts/generate_voice_clone.py --reference-audio "<本人参考.wav>" --i-own-this-voice --text-file "<单句UTF-8文本.txt>" --assets-dir "<已核验资产目录>" --request-id "<唯一编号>"
```

输出默认保存在 `.runtime/voice_clones`，不会自动发送。固定 4096 上下文、4 条计算线程，启动前需要至少 7 GiB 可用提交内存及 4 GiB 空闲显存，运行中低于 1 GiB 提交余量就停止自己的合成进程。提交余量与空闲物理内存不同；本机实测曾在物理内存仍有余量时耗尽提交上限。未知或已完成的编号都不重发。

Windows 已有一份真实本机试听：使用本人确认的约 6 秒参考录音，合成约 3 秒新语句，用户反馈“音色接近”。这只是一份案例，没有发表参考录音、生成声音或声线特征，不代表其他设备或其他录音都能得到相同效果。

音频生成成功不证明音色、口气或文本内容完全一致；先试听核对，再决定是否启用。应让 GPU 与系统内存不足时停止该条任务，避免阻塞微信文字回复。

本项目没有声纹身份验证，也不承诺克隆效果与真人完全相同。Windows 微信 4.1.15.13 的独立本机原型已核验一次明确批准的原生 type34 发送，包括新本人消息、非零服务器编号、XML 与对应音频哈希。这个单例不代表公开版本已提供通用语音发送接口；公开生成命令仍只产生本机试听，不自动发给联系人。

## 何时建议语音

审核台使用 `app.voice_reply_policy` 给出回复方式建议，不改变现有回复正文、风险审核和文字发送流程。明确的本轮语音请求可建议先生成短语音试听；习惯路径另需同联系人、近期且经本人确认的手发样本。媒体观察和转写本身不能证明手发；只有另有本人确认、所属账号与来源匹配且排除已知 AI 发送时，才统计其原始回复方式。未知来源不统计，确认不覆盖后续新消息。没有可靠样本时默认文字。

明确要文字或不方便听、群聊、22:00–08:00、含金额/日期/地址/代码/链接、专业问题、争执、转写不确定、待确认事实和中断恢复等情况优先文字。引用、转发、否定、延后请求及音频附件不能当成本轮微信语音请求。建议语音以约 15 秒以内为目标；朗读秒数只是估算，不是生成耗时。默认先试听；本人另有明确授权时，普通低风险语音可以免试听自动发送，重要事项的审核条件继续生效。

## 明确授权后的自动语音

`outbound_voice` 默认关闭。需要本人确认的本机声线参考、固定模型资产、私有输出目录，以及另行安装并核验的版本匹配原生发送器。公开 Python 客户端不附带私人录音、账号授权或本机发送 DLL；仅打开配置开关不足以发送。后台还核对本人独立授权、当前账号、参考音频哈希、未过期会话和发送能力。

自动路径只在文字回复已通过原审核规则后，按当前请求或可信语音习惯选择；不把每条回复都改成语音。单语音生成槽避免并行加载声线模型，资源不足或接口不可用时在尝试语音发送前沿用文字。TTS 子进程最多运行 60 秒，完整哈希核验、编码和回执另计；同一模型通道可能等待这次处理，并不代表全部回复无等待。

真正尝试发送前保存永久记录，只有精确原生语音回执通过才记已发。结果未知时保存 `voice_unknown`，禁止自动或普通草稿批准后补发同轮文字；先核对回执。AI 语音写入独立发送账本，不作为本人手发习惯。

## 生成速度与计时

生成报告新增 `timings_seconds`，分别记录资产核验、资源检查、CLI/参考音频核验、原生进程、音频检查和格式转换。`native_run` 包含资源复查、冷加载及子进程等待；`total` 截止报告准备完成，不包含最后写入记录或微信发送。已完成/未知请求编号仍禁止重跑。

一次本机样本输出 2.48 秒音频：原生日志的核心计算为 0.81 秒，进程启动到写出 WAV 约 3.09 秒；此前没有完整 CLI 或微信回复时延记录。另一次只读全资产核验为约 9.06 秒，两次数据不能拼成某次完整时延或平均值。新增计时本身不代表提速。

当前仍按需启动官方 [b10679 TTS 程序](https://github.com/ggml-org/llama.cpp/blob/b10679/tools/tts/tts.cpp)，没有已验收的常驻模型或参考声线缓存服务。短句、直接从已核验 WAV 编码 SILK 可避免不必要的等待和 MP3 往返；不能为提速跳过哈希、降低资源门槛或未经确认重复发送。

## 微信语音封装与解码试听

`app.outbound_voice` 将已核验的本机单声道 PCM16 WAV 编为 Tencent SILK，并完整解析每个 20ms 帧、再解码核对时长和非静音。使用已安装的 `silk-python==0.2.8`（导入名 `pysilk`），不下载模型、不读取聊天记录、不调用微信发送接口。

```text
python -m app.outbound_voice --source-wav "<私有试听.wav>" --output-dir "<私有本机输出目录>" --request-id "<全新唯一编号>" --expected-source-sha256 "<WAV的SHA256>"
```

源音频和输出必须位于公开源码目录之外的私有本机路径；网络共享以及解析后指向网络共享的链接均拒绝。调用者还应避免其他公开或云同步目录。默认限 1–30 秒，支持 8/12/16/24kHz。短于完整帧的尾部仅补零到下一帧；原音频哈希、补零数量和最终时长分别记录，不把有损解码误称为原始 PCM。

产物为 `voice.silk`、`roundtrip.wav`、`manifest.json` 与持久请求记录。读取产物时重新核验哈希、每帧长度和解码时长；pending、unknown、done 或未完成目录均阻止同编号再次编码。Manifest 的 `send_authorized`、`native_send_verified` 和 `voice_sent` 均为 false，不能用修改 JSON 的方式授予发送权限。

本机实际测试已将一份 2.96 秒本人试听编成 148 个完整语音帧，并解码回 2.96 秒可听 WAV。这个封装结果与上述原生发送单例分别验收；每次真实发送仍需绑定具体批准、音频哈希及服务器回执。文件附件发送不能替代真正的语音消息。

编解码 API 参考：[pysilk 固定版本源码](https://github.com/synodriver/pysilk/tree/b0fbba74506bb8be23ef5e120b983bbb2f70ac19)。本项目没有复制或分发其编解码源码和二进制；其包元数据声明 BSD，底层 Skype SDK 有独立许可及不授予专利权的声明，分发依赖时须另核对。

协议参考：[豆包 TTS 连接实现](https://github.com/ljheee/tts-extension)。该仓库未提供许可证，本项目只参考协议行为，未复制其源码。

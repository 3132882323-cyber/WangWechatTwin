# 表情图片库与接口

当前实现将表情包原图作为微信图片消息发送（类型 3），不切换聊天、不点击微信界面。微信原生收藏表情（类型 47）的接口尚未完成，不能用图片验收代替其验收。

微信 4.1.15.13 本机已验证：`/SelfTestImageLayout` 不发送自检 → `/SendImgMsg` 实际发送 → 新本人图片消息 → 原图 MD5 与服务器编号核对。只重试数据库读取，不重复发送结果不明的请求。

## 识别与缓存

- 保存 MD5 验证后的原图，不把抽帧预览当成原图。
- 动图按播放时长取 15%、50%、85% 的位置，再移除完全重复的画面；最多附三张图。
- 透明图片合成白底，限制图片尺寸、文件大小和动画帧数。
- 原图及预览分别校验，损坏预览从原图恢复；文件更新先写临时文件再原子替换。
- 仅有 MD5、没有 CDN 地址的消息可以复用已校验原图。认证账号目录中的本机素材也必须匹配 MD5；加密缓存不当作明文图片。

## 本机配置

默认禁用，现有项目应追加配置，勿覆盖用户密钥和数据库：

```yaml
stickers:
  enabled: true
  catalog: .runtime/history_reader/sticker_catalog.json
  max_per_contact_per_day: 3
  port: 30004
  bootstrap_manifest: .runtime/local_api/native_media/manifest.json
```

安装已编译的原生连接到 `native_media` 后，沿用原生文字连接的账号探针与哈希清单规则，设置 `port.txt` 为对应端口。图片接口仅接受同安装目录下 `approved_assets` 的已批准图片，不接受任意文件路径或网络文件。此媒体连接与已有文字端口分开部署，不覆盖正在使用的文字 DLL。

私有表情库结构：

```json
{"items":[{"id":"<原图MD5>","label":"这是好事啊","approved":true,"tags":["celebrate"],"original":"<MD5>.jpg","preview":"<MD5>-0.png","preview_sha256":"<预览SHA256>"}]}
```

文件位于本机 `history_reader/sticker_assets`；真实图片与联系人不随仓库发布。当前收到明确的考试通过、成功、拿到 offer 等好消息时，低风险判断后建议一张庆祝图片。建议只进入审核台，逐条批准后才通过接口发送；报价、合同、付款等语境不自动产生庆祝建议。群聊表情发送未开放。

该选择器目前是有限语境规则，不宣称理解全部表情语义或复制本人完整风格。测试草稿没有真实联系人，按钮只能保存，不能发送。

# 豆包日常通道与会话恢复

日常文字、语音本机转写后的文字、图片与表情包可统一交给豆包。专业问题、明显激动情绪与高风险请求仍路由到 GPT；是否自动发送由原审核及发送规则决定。

现有 `hybrid_web` 配置增量示例：

```yaml
openai:
  provider: hybrid_web
  everyday_lane: doubao
  disabled_lanes: [deepseek]
  deepseek_drafts: false
  local_proxies:
    deepseek:
      enabled: false
    doubao:
      enabled: true
```

上面只展示改动字段；保留既有端点、密钥文件引用、超时和共用会话数据库。默认日常通道仍为 `deepseek`，老配置兼容。禁用通道不会构建网页客户端、领取网页任务或作为备用通道；与启用代理、对照草稿等矛盾配置会直接报错。

旧的三路网页恢复接口会在存在禁用通道时拒绝执行，也不会下发遗留恢复请求。此版本没有实现按部分通道重建网页，不要使用三路恢复按钮重新打开停用账号。

## 失败后的处理

同一外部消息编号不能因换本地通道或重启而重复提交。进行中的请求保持阻断；未知结果、旧会话编号及历史代次保留，不清库。后续**新消息**只有在本地微信记录完整、媒体指代已解决时，才能隔离旧模型会话并重建上下文。每个联系人与通道单独退避，避免一位联系人阻塞其他聊天。

模型摘要、旧候选和未发送草稿不会用于恢复本人事实。语音听写不确定、图片信息不完整或指代未识别图片时仍转审核。发送接口自身的未知结果保护保持原样。

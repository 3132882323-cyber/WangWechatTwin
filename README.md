# 微信聊天记忆分身

一个在 **Windows 本机运行**的微信回复助手：先读懂这段对话是谁在说、说过什么，再参考本人给这位联系人的实际表达，生成草稿或在授权范围内回复。

它关注的是个人聊天记忆和交流习惯，不预设用户是老板，也不把某个联系人或旧项目中的人物当成本人。仓库地址中的 `WangWechatTwin` 是历史工程名称，**不代表用户身份**。

## 怎样理解一段聊天

- 区分本人、当前联系人和引用中的第三人。别人说的“我”，不自动变成本人的经历。
- 按联系人保存日期、说话人和原文依据。检索相关话题时带回前后交流，不只抽一句话。
- 优先学习本人亲手修改的回复，再参考相似情境原话、当前联系人习惯和全局表达统计。
- 旧报价、计划、情绪和承诺不是今天的事实。没有本人立场依据时，不替本人编理由、作决定。
- 不把另一个联系人的私聊原文混入当前对话，不宣称复制了完整人格。

| 主动问候与话题跟进 | 本机已生成并显示 3 条审核草稿；默认关闭，启用后仍须逐条批准；间隔、每日上限与未回复检查已接入 |
| 表情图片接口发送与审核建议 | 原图通过本机 HTTP 发送，已核验新的本人图片消息、同图 MD5 与服务器确认；建议先审核。微信原生收藏表情类型 47 尚未完成接口验收 |

| 文件、视频及其他未解析内容 | 留审核，不假装看懂 |

GPT 网页连接使用“不个性化临时聊天”，只输入微信任务所需上下文，不读取已有网页对话。API 和 Codex 账号连接仍可选；不同产品额度有各自边界，不保证无限使用。连接失败不会偷偷回退到 Codex。

自动发送默认关闭。日常低风险回复须明确开启；钱款、合同、账户、责任及缺乏事实依据的承诺留审核。发送前核验账号和联系人，发送后读取新的本人消息及服务器编号；这不等于联系人已读。图片识别或窗口状态不明确时停止该条处理。

## 安装

环境：Windows 10/11、Python 3.10–3.12。微信 GUI 兼容目前严格校验 `4.1.15.13`，其他版本不能据此保证可用。

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install wxauto4==41.1.7
```

确认没有已有配置后，再从 `config.example.yaml` 与 `.env.example` 创建自己的配置。**不要覆盖已有密钥、配置或数据库。**双击 `START_HERE.bat` 可进入本机菜单。

仅连接本人有权访问的已登录微信账号：

```powershell
.venv\Scripts\python.exe scripts\connect_local_history.py --db-dir "<本人账号db_storage绝对路径>" --i-own-this-account
.venv\Scripts\python.exe -m app --config config.history.yaml run --mode shadow
```

先完成只读、草稿、明确测试联系人与内容的发送验证，再按需要开启 `low_risk_auto`。群聊单独授权，默认只处理 @ 本人的消息。公众号和系统通知不自动回复。

网页模型连接见 [扩展说明](browser_extension/README.md)，角色与人物记忆见 [角色画像说明](ROLE_PROFILE.md)，本机 HTTP 接口的条件与未完成项见 [接口连接说明](docs/LOCAL_HTTP_TRANSPORT.md)。本机审核台由配置中的 `web.port` 决定，只应监听本机。

主动聊天见 [审核规则](docs/PROACTIVE_CHAT.md)，表情图片库与接口见 [表情图片说明](docs/STICKER_IMAGES.md)。

语音、图片和表情的识别安装及验收边界见 [媒体识别说明](docs/MEDIA_RECOGNITION.md)。

## 隐私与源码

原始整库、联系人画像、缓存、数据库、密钥和配对码留在用户本机，不随仓库发布。只有经授权的当前联系人必要上下文与当前媒体会发送到所选网页模型。微信客户端、托管模型和可选外部 GUI SDK 不属于本项目源码。源码使用 **Apache-2.0**；第三方许可证见 [NOTICE](NOTICE) 与 [第三方说明](THIRD_PARTY_NOTICES.md)。

```powershell
.venv\Scripts\python.exe -m pytest -q
node --test browser_extension/pool.test.cjs
```

源码检查与少量真实案例不代表全部微信版本、所有媒体类型或长期运行都可靠。报告问题请提交合成或脱敏样例，阅读 [隐私说明](PRIVACY.md)，不要上传真实私聊和凭证。

## 模型分工与独立后台

`openai.provider: hybrid_web` 将日常文字与离线语音转写交给 DeepSeek；图片、表情包交给豆包；专业问题与明显激动情绪交给 GPT 最高思考档。DeepSeek 深度思考、智能搜索关闭。三个独立队列共用本机审核与原生发送规则；争执升级和重要承诺先审核。

独立个人数据库保存双方交流，并区分 AI 发送、自动听写、本人纠正与来源不明确的历史内容。新消息读取与模型生成分离，发送前核对本人新发言及更晚入站消息，阻止过时回复。审核台支持纠正原文后重新起草。

Windows 登录启动可通过当前用户 Startup 快捷方式，依次启动选定 VPN、微信、已配对浏览器和后台；复用已有进程，避免两个 VPN 同时启动。启动 VPN 应用不等于自动连接，实际重启须单独验收。

DeepSeek、豆包各保留一个专用网页，在同一页内新建或切换联系人对话，按微信备注命名（豆包标题受网页 20 字上限约束，本机保留完整备注）。联系人识别仍使用独立会话标识，重名或修改备注不会合并聊天。群聊遵循仅处理 @ 本人的配置。


### 稳定性与媒体后续文字

后台使用独立 DeepSeek/豆包/GPT 生成队列。表情、图片与随后补充的文字分开排队，文字不等待识图；发送前继续核对最新入站和本人发言。中断任务恢复为审核草稿，不自动重发发送状态不明的内容。任务结果持久化，用于避免重复处理。

本人语气样本优先使用有来源的当前联系人手发内容，并排除 AI 回执及发送尝试；来源不明确的历史仅作线索。离线语音加入词级置信度、停顿时间和当前联系人提示词；数字、含糊词及重复幻听留审核，不强行纠正人名。

DeepSeek 压缩重复上下文和输出格式，在已有专用窗口中点击新建对话；已有联系人的保存对话优先从侧栏恢复。网页断连未领取任务时快速留审核，断线后重连。表情识别区分可见内容与对最近交流的语境推断，允许对自然收尾选择不追加回复。

正式运行不需要 Codex 控制鼠标或键盘：本机端口派发模型任务，扩展自主处理网页并回传；微信通过原生 HTTP 接口发送。网页模型这一侧仍是页面自动化，不是厂商官方 API。网页服务可能慢或断开；DeepSeek 单轮生成 45 秒、豆包 75 秒超时后留审核，不让过期结果发送。

并发审批按联系人和草稿 ID 隔离；恢复任务不与新消息合并，保留原始防重身份。网页派发包含本轮标记，回传须关联本轮用户消息后的答复，并核验精确会话 URL。

## 持续运行与故障恢复

Windows 后台可使用 `python -m app.supervisor --config config.http-api.yaml` 持续运行。看护只管理自己启动的进程：异常退出会逐步延迟重启，十分钟没有主循环心跳时安全恢复；正常退出或 `.runtime/startup/STOP_SUPERVISOR` 会保持停止。原有暂停状态不会被看护取消。

消息合并按原始消息 ID 去重，内容、队列任务与媒体解码均有限额。超限任务保留原记录并进入审核，不调用模型；中断任务恢复后不直接自动重发。系统可用提交内存低于 1 GB 时暂停领取新任务，释放压力后继续。审核台 `/health` 同时报告三条回复线程及主循环心跳，不能只凭网页心跳判断完整收发成功。

GPT 网页通道默认精确选择 GPT-6 与 Pro 最高强度，仍使用不个性化临时聊天；DeepSeek 与豆包分工不变。

可在管理员 PowerShell 中执行 `scripts/install_watchdog.ps1` 注册独立 Windows 后台任务。任务在用户登录后运行，每分钟检查一次启动机会，同一任务仍运行时忽略重复触发。卸载或主动完全停止看护时先禁用 `WangWechatTwin-Backend` 任务；普通暂停回复仍使用审核台暂停按钮。

进程归属和 Windows venv 启动器识别复用现有 psutil（BSD-3-Clause；[源码与许可](https://github.com/giampaolo/psutil)），不管理其他应用进程。媒体流式解码复用已安装的 pysilk 0.2.8，网络连接生命周期参考 Chrome 官方样例，未复制第三方代码。

## 后台专用窗口与内部候选

模型网页仍使用浏览器进程和原登录 profile，但桥接器把可证明归属本项目的固定标签移入独立窗口。Windows 端核对随机登记标题、Chrome 程序路径、当前用户和进程身份后真正隐藏，并以 `IsWindowVisible=false` 验证；不是只最小化。普通用户网页不会迁移。审核台提供“显示后台网页”和“完成操作，恢复后台”，临时显示时暂停新网页任务，已有任务可能完成。误激活后台模型标签会恢复控制页并再次隐藏，手动显示模式不抢回窗口。

日常回复在一次模型输出内生成 A/B/C 三条候选，再按安全、边界、语境、本人表达与自然续聊次序选择一条；这些 0–5 分是主观排序，不能称为真实概率。专业知识及业务问题直接生成答案。未入选候选不作为人工风格样例，格式不完整、含虚构标记或不安全的选择进入审核，不追加三次模型请求。若对方直接询问 AI 身份，继续如实说明。

Chrome 窗口和标签迁移使用[官方 Windows API](https://developer.chrome.com/docs/extensions/reference/api/windows)及[Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)；本机隐藏适配自行实现，候选比较参考 [BEST-Route](https://github.com/microsoft/best-route-llm) 思路，没有复制第三方代码或新增模型依赖。


三路恢复控制页现使用本机 HTTP：`http://127.0.0.1:18769/browser-window/host`。扩展重载后恢复请求通过配对接口接收，按已登记会话地址重建失效标签，再核验窗口和恢复请求编号；不会把普通用户页面认领为后台页。恢复确认只证明页面连接恢复，实际回复仍须单独验证。
